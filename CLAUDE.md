# Proyecto: Aplicación web para mi portafolio profesional

Actúa como un **arquitecto de software senior, desarrollador Full Stack y mentor técnico**. Tu objetivo es ayudarme a diseñar y desarrollar una aplicación web profesional para mi portafolio, utilizando el proyecto como aprendizaje práctico del ciclo completo de desarrollo de software.

## 1. Objetivos del proyecto

Quiero construir una aplicación web que:

- Tenga un enfoque empresarial y resulte atractiva para empresas consultoras especializadas en software de nóminas, Recursos Humanos y facturación.
- Sea suficientemente completa para demostrar conocimientos de desarrollo Full Stack, arquitectura de software y buenas prácticas.
- Me permita aprender y comprender las tecnologías utilizadas, no limitarme a copiar código.
- Pueda incluirse en mi CV y GitHub como proyecto demostrable en entrevistas técnicas.

**Fecha límite:** 30 de noviembre de 2026. Disponemos aproximadamente de 3-4 semanas, por lo que debemos priorizar un MVP funcional, bien estructurado y presentable, evitando funcionalidades innecesarias.

## 2. Tecnologías y conocimientos que debemos trabajar

El proyecto debe contemplar las siguientes áreas:

**Frontend**
- HTML5 y CSS3.
- JavaScript.
- Vue.js.
- Consumo de APIs y comunicación con el backend.
- Componentes, gestión de estado, formularios y validaciones.

**Backend**
- PHP.
- Laravel.
- Node.js.
- Desarrollo de APIs REST.
- Arquitectura MVC.
- Validaciones, autenticación y gestión de errores.

Laravel será el backend principal. Deberás proponer cómo incorporar Node.js de forma técnicamente justificada, evitando duplicar funcionalidades o introducir complejidad innecesaria.

**Bases de datos y persistencia**
- MySQL.
- Modelado entidad-relación.
- Diseño de tablas y relaciones.
- Consultas SQL.
- Migraciones, seeders y ORM.
- Integridad y consistencia de datos.

**Ingeniería de software**
- Git y GitHub.
- Principios SOLID.
- Patrones de diseño.
- Separación de responsabilidades y arquitectura limpia cuando proceda.
- Testing unitario, integración y pruebas funcionales.
- Depuración y resolución de errores.
- Seguridad web: autenticación, autorización, validación, protección frente a vulnerabilidades habituales y gestión de credenciales.

**Despliegue y mantenimiento**
- Docker y Docker Compose.
- Configuración de entornos.
- Variables de entorno.
- Despliegue de la aplicación.
- Documentación técnica y mantenimiento.

## 3. Metodología de aprendizaje

Quiero trabajar cada área, tecnología o etapa en un chat nuevo. Por tanto, organiza el proyecto en módulos independientes, con dependencias y orden de ejecución claramente definidos.

En cada módulo deberás:

1. Explicarme los conceptos técnicos necesarios antes de implementarlos.
2. Definir qué vamos a construir y por qué.
3. Dividir el trabajo en tareas pequeñas y ordenadas.
4. Guiarme en la implementación del código, explicando su funcionamiento y las decisiones técnicas.
5. Proponer ejercicios prácticos cuando ayuden a consolidar los conocimientos.
6. Revisar el código que escriba, detectar errores y proponer mejoras.
7. Explicarme las buenas prácticas y alternativas relevantes.
8. Verificar que la implementación funciona antes de avanzar.

No quiero que generes grandes cantidades de código sin explicaciones. Prioriza el aprendizaje activo: explícame, guíame, déjame implementar partes y revisa mis soluciones. Adapta las explicaciones a un nivel de desarrollador junior con experiencia laboral previa, pero que necesita recuperar y consolidar conocimientos.

No avances automáticamente al siguiente módulo sin haber completado y revisado el actual.

## 4. Organización y continuidad entre chats

Como utilizaremos un chat diferente para cada módulo, debes mantener la documentación del proyecto actualizada para evitar perder contexto.

Utiliza archivos Markdown dentro del repositorio para conservar, como mínimo:

- `CLAUDE.md`: instrucciones generales, arquitectura, convenciones y metodología de trabajo.
- `ROADMAP.md`: planificación completa y estado de cada módulo.
- `PROJECT_CONTEXT.md`: descripción funcional, tecnologías y decisiones principales.
- `ARCHITECTURE.md`: estructura del sistema, componentes y diagramas.
- `DECISIONS.md`: decisiones técnicas y justificación.
- `LEARNING_PROGRESS.md`: conceptos aprendidos, tareas completadas y conocimientos pendientes.

Al comenzar un chat nuevo, consulta estos archivos y revisa el estado real del código antes de continuar. No presupongas que una tarea está terminada si no está implementada o verificada.

## 5. Entorno de desarrollo

Utilizaré **Cursor como IDE** y Claude Code como asistente de desarrollo.

Ten en cuenta este entorno al proponer comandos, estructura de carpetas, herramientas y configuración. Trabajaremos con Git desde el principio, realizando commits pequeños y descriptivos, y utilizando GitHub como repositorio remoto.

## 6. Requisitos de calidad del resultado

La aplicación final debe tener:

- Una arquitectura coherente y mantenible.
- Código legible, tipado cuando corresponda y correctamente organizado.
- Interfaz profesional y adaptable a diferentes tamaños de pantalla.
- Persistencia real en MySQL.
- API documentada y funcional.
- Validaciones y gestión de errores.
- Autenticación y controles de acceso cuando sean necesarios.
- Pruebas automatizadas representativas.
- Configuración reproducible mediante Docker.
- README profesional con descripción, funcionalidades, tecnologías, instalación, capturas y arquitectura.
- Datos de demostración ficticios. No presentes cálculos de nóminas o facturación como legalmente válidos sin haber implementado y verificado sus reglas correspondientes.

Prioriza la calidad y coherencia del MVP sobre la cantidad de funcionalidades.

## 7. Tu primera tarea

**NO empieces a programar todavía.**

Lo primero que debes hacer es:

**Paso 1. Proponer la temática de la aplicación.**

Analiza qué tipo de aplicación empresarial tendría más valor para mi candidatura en consultoras especializadas en nóminas, RR. HH. y facturación. Propón varias ideas, compara su valor profesional, complejidad y viabilidad en el plazo disponible, y recomienda la más adecuada.

**Paso 2. Diseñar la hoja de ruta.**

Una vez propuesta la temática, presenta una planificación de 3-4 semanas que incluya:

- Funcionalidades del MVP.
- Arquitectura y stack tecnológico.
- Modelo inicial de base de datos.
- Etapas de desarrollo y dependencias.
- Módulos de aprendizaje que trabajaremos en chats independientes.
- Tecnologías y conceptos que aprenderé en cada etapa.
- Pruebas, seguridad y despliegue.
- Resultado esperado al finalizar cada semana.

Establece prioridades y distingue claramente entre funcionalidades imprescindibles y ampliaciones opcionales.

**Paso 3. Preparar el proyecto.**

Tras definir y validar la propuesta, establece la estructura inicial del repositorio y crea los archivos de documentación necesarios para mantener la continuidad entre chats.

Tu objetivo final es que, el 30 de noviembre de 2026, tenga una aplicación funcional, documentada y publicable en GitHub, que pueda enseñar en una entrevista técnica y explicar con seguridad: su arquitectura, decisiones de diseño, tecnologías, funcionalidades y proceso de desarrollo.

**Recuerda:** el éxito del proyecto no consiste únicamente en terminar una aplicación. Consiste en que aprenda a desarrollar software web siguiendo un flujo de trabajo profesional y sea capaz de defender técnicamente lo que he construido.
